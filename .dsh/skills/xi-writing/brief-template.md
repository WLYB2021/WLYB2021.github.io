# 文章 brief

> 用法：复制这份文件，填四块内容，交给写作 agent。
> skill 管「怎么写」，brief 管「写什么」。

## 主题

（一句话：这篇文章讲什么。）

## 核心

（一条主线，3–6 个短句。每句一个环节，连起来要像同一件事的几个阶段，而不是几个话题。
主线里的关键词先给一句定义，别让模型自己猜。）

固定三条，不用改：

- 每层五拍：旧写法长什么样 → 哪个假设失效了 → 转变怎么发生 → 之后是什么样 → 代价是什么。
- 层与层要接上：上一层交出去的东西，正好是下一层要处理的问题。
- 凡是落不到这条主线上的材料，再有意思也不写。

## 层面与载体

（每一层写明：从什么变成什么，以及用哪些大家熟知的东西来讲。
载体是论据，不是清单——每一样都要讲清楚它换掉了什么，不要展开成 API 手册。）

1. （层面）：（A → B）。用（读者最熟悉的几样东西）来讲。
2. （层面）：（A → B）。用（读者最熟悉的几样东西）来讲。
3. （层面）：（A → B）。用（读者最熟悉的几样东西）来讲。

## 不要写

- 边角细节：（这一篇不该展开的技术细节）
- 横向对比清单（如果主题不是这个）
- 读者画像

## 标题与 slug

- 标题：（新起，或沿用哪一篇）
- slug：（沿用旧文就用旧 slug，新开就起一个英文短句）
