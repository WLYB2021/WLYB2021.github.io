# 正文排版规则

一句话总纲：**空行管"分层"（Markdown 语法），CSS 管"间距"（视觉）。** 两者别混。

- 空行决定"这是不是一个独立的块"——它是**语法**，省不掉；
- 块与块之间留多少——那是**样式**，由 CSS 的 `margin` 决定，跟空行个数无关。

## 一、空行规则

### 为什么不能"取消空行"

Markdown 用空行切块。删掉空行的后果是**结构坍塌**，不是变紧凑：

```markdown
## 一、单体
这是第一段。
接着这句话会被并进上一段。      ← 没有空行 → 两段合成一段
```

- **段落之间**没空行 → 合并成一段（软换行）；
- **列表 / 代码围栏 / 引用块前**没空行 → 常被吞进上一段或解析错；
- **连续 N 个空行 ≡ 1 个空行**（HTML 空白折叠），多打的空行既无效、又该避免。

### 规则（四条）

1. **块与块之间恰好 1 个空行**——段落、标题、列表、代码块、表格、引用块彼此之间。
2. **禁止连续 2 个及以上空行**。多出来的不会让间距变大，只会污染 diff。
3. **禁止行尾空格**（代码块内除外）。
4. **列表项之间不空行**。空行会把整个列表变成 loose list——每项被包进 `<p>`，行距突然变大，且项距不再受 CSS 控制。

> 首行 `引子` / 末节 `结语` 这类"书挡"标题，也照样前后各留 1 个空行。

## 二、间距由 CSS 控制（不靠空行）

所有垂直间距在 `assets/css/extended/custom.css` 里定义，**当前刻度**：

| 元素 | 上间距 | 下间距 | 备注 |
|---|---|---|---|
| 段落 `p` | `--ed-read-para`（默认 .95em） | 同左 | 已变量化，阅读设置面板可调 |
| `h2` | 2em | .75em | 带下边框 |
| `h3` | 1.65em | .6em | |
| `h4` | 1.4em | .5em | |
| `h5` | 1.2em | .45em | |
| 标题后的首个 `p` | .2em | — | 收紧，避免标题与正文脱节 |
| 列表 `ul` / `ol` | .95em | .95em | |
| 引用块 `blockquote` | .5em | .5em | |
| 代码块 / 表格 | 1.6em | 1.6em | |

**待办（未做）**：目前只有段距是变量，标题/列表/代码/表格仍是写死的 em。计划把它们抽成一套"块间距刻度"变量（以字号为基数，读者调字号时整体等比缩放）。这属于版式改动，会全站生效，所以放在内容精修之外单独做。

## 三、校验

写完文章跑一次：

```bash
python3 scripts/lint-prose.py        # 校验 content/posts/*.md
python3 scripts/lint-prose.py x.md   # 校验指定文件
```

Windows（无 `python3` 命令时）：

```bash
python scripts/lint-prose.py
```

有 `make` 时：`make lint`。

脚本按上面四条规则逐行检查，输出 `文件:行号:问题`，有问题时退出码为 1（CI 会因此中断构建）。规则本身以本文档为准。
