这是一篇**示例文章**，用来演示 PaperMod 的排版效果和 front matter 字段用法。你可以直接删掉它，或者照着这个结构写自己的第一篇。

## Front matter 字段说明

每篇文章开头是 front matter，用来定义元数据：

| 字段 | 作用 |
|---|---|
| `title` | 文章标题，显示在列表和页面顶部 |
| `date` | 发布日期，决定文章在归档中的排序 |
| `tags` | 标签，用于主题分类 |
| `categories` | 分类 |
| `description` | 摘要，显示在文章列表页 |
| `summary` | 覆盖自动摘要，用手写的前几句 |

其中 `description` 和 `summary` 有区别：`description` 用于列表页卡片，`summary` 用于首页文章卡片。都不写的话，Hugo 会自动截取前 30 个字符（可在 `hugo.toml` 的 `summaryLength` 调整）。

## 正文排版演示

### 标题层级

支持三级标题，左侧会自动生成目录（可在配置里关闭）。

### 列表

无序列表：

- 第一项
- 第二项
  - 嵌套项

有序列表：

1. 第一步
2. 第二步
3. 第三步

### 代码块

```kotlin
// 语法高亮由配置中的 markup.highlight.style 控制
fun main() {
    println("Hello, Hugo!")
}
```

行内代码用反引号包裹，比如 `git commit -m "message"`。

## 关于这条提示

文章底部会自动出现评论区（需要先配置 Giscus）。单篇不想显示评论的话，在 front matter 里加：

```yaml
disable_comments: true
```

## 写作建议

技术博客的价值在于**让后来的人少走弯路**，所以比起"记录做了什么"，更值得写的是：

- **为什么这么做** —— 权衡和取舍的理由
- **踩了什么坑** —— 那些查资料查不到的隐性陷阱
- **数据与现象** —— 用量化信息支撑结论

以上都是模板占位内容，开始写你自己的吧。
